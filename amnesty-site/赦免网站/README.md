# 鲸鱼娘的人类保留计划 · 前端交付包

## 怎么打开
- `dist/index.html`：活动首页。双击即可用浏览器打开，无需安装；角色、底胚、标题字体均内嵌，B 站头像加载需要联网。
- `dist/archive.html`：直接进入完整名册的独立入口。
- 两个文件都包含完整素材及数据；首页内也可以用导航切换全页名册（`#/archive`）。
- 可将 dist 下这两个 HTML 放到静态网站托管服务上。当前交付没有替你公开部署，也没有服务端。

## 本版完成的内容
- 原版鲸鱼娘五种表情、重做的活动首页、戳角色的小彩蛋。
- “评论区求生实录”：从原文件选取实际第一人称求赦免留言，自动横向滚动、手动翻、暂停；鼠标悬停、键盘聚焦及系统减少动态效果时暂停。点击可看完整原话及来源内容。
- 完整名册：全部相关账号、UID/昵称全量搜索、每页30/60/120人、跳页、定位某人。默认只展示 UID 尾号。
- 个人档案：原话、来源时间和来源视频/动态链接，同一 UID 多条留言可展开。
- 免死鲸牌、丹书铁券，两件不同的收藏品，可切换、翻面、保存高分辨率 PNG。人物使用用户提供的原图，饰品底胚由 AI 生成；文字由 Canvas 真实绘制。
- 海报默认 UID 尾号，勾选可显示完整 UID。签发记录仅保存在浏览器。

## 数据边界（发布前必读）
原文件是“赦免相关评论”，不等于经过确认的最终资格名单。当前保留全量 579 条来源评论、按字符串 UID 合并的 549 个账号；其中也有作者回复和相关讨论。没有擅自删人或冒充完成资格审核。
滚动实录排除了鲸鱼娘账号自身回复及无关讨论，选取部分不同内容展示；完整原话仍在各人档案内。

**静态 HTML 包含完整 UID、昵称、评论和来源。页面上的 UID 打码只是显示策略，不能隐藏源数据。**
公开前请确认用户昵称及评论的展示授权、最终纪念领取名单，以及需要移除的账号/评论。
本页不验证 UID 的所有权、不证明领取者是账号本人，不能作为真实权益或兑换凭据。
纪念图无法律效力，不承诺现实安全；页面是野生二创、非 DeepSeek 官方。

## 扩充名单
1. 将后续同格式 CSV 放到本目录。
2. 运行 `python import_comments.py 新评论.csv`。默认追加/合并，UID 全程按字符串，不丢失大数字精度；既有档案编号保持稳定；相同原话+时间+来源不会重复导入。
3. 检查 `data.json`，手动确认或移除不适合公开/领取的记录。
4. 运行 `python build.py`，新的离线网页会生成到 dist。

若需删除某人，在 data.json 中移除该记录，再构建。不建议直接编辑 dist 里的内嵌数据。
新增数据后，主页人数、完整名册及搜索自动更新。首页求生实录的精选 UID 在 app.js 中的 `featuredIDs` 配置。

## V4 字体与统一窗口
- 免死鲸牌使用站酷庆科黄油体，标题呈几何铭刻风；丹书铁券使用马善政毛笔字，主标题、鲸谕、签批同步处理。动态昵称和长评论保留可读性优先的字体。
- 字体以 WOFF 字符子集内嵌在两份 HTML 中；不依赖外部字体服务，Canvas 等待字体加载后再绘制，保存 PNG 同样带新字形。
- 统一收藏弹窗和展示区尺寸。桌面弹窗宽 1080px、展示区高 660px（小屏按可用空间滚动）；手机两种均采用同一视窗高度。切换时不改变外框或拉伸原图。
- 图片输出保留适合各自形状的比例：鲸牌 1080×1440；铁券 1600×1100。“窗口一致”不等于把横券强行拉成长牌。
- 字体授权：assets/fonts/*-OFL.txt。WOFF 是当前固定文案的子集；如果新增书法/铭刻标题中的汉字，需要重新生成相应子集。新增名单不影响普通昵称、评论显示。

## 自动更新与部署（2026-10-23 起）

一条命令完成「抓取 → 合并 → 补头像 → 重新打包」：

```bash
python amnesty-site/refresh.py --fetch                 # 增量：每个内容翻到上次水位就停
python amnesty-site/refresh.py --fetch --full          # 全量重抓（约 70 分钟，每周对账用）
python amnesty-site/refresh.py --fetch --no-private    # 本轮不抓私信
python amnesty-site/refresh.py --source 某评论.csv     # 离线导入已有 CSV
python amnesty-site/refresh.py --fetch --dry-run       # 只看会新增多少人，不写文件
```

**为什么要增量**：账号现有 6 个投稿 + 15 条动态，接口合计约 17.7 万条评论，实测抓取速率约 43.6 条/秒 —— 全量一次约 70 分钟。每 2 小时跑一次全量，一个月要 24000 分钟，免费额度只有 2000。所以常态是增量：

- 评论按时间倒序翻，翻到比水位更旧的整页就停，单次通常十几秒
- 水位存在 `crawl-state.json` 的 `contents`（键形如 `视频:<aid>` / `动态:<oid>`），只按根评论的时间推进
- 水位之前 24 小时内的楼中楼仍会重扫（`--thread-window-hours`），避免漏掉「老评论下新冒出来的回复」
- 每周日跑一次 `--full` 对账，补增量扫不到的角落
- 水位只在 `data.json` 落盘成功后才前进；中途失败下一轮重抓同一段，靠 `merge_rows` 去重

**私信**：`export_private_messages()` 走 `get_recent_private_messages()`，只打开最近 `--private-window-minutes`（默认 180）内有过消息的会话。账号有 3200+ 个私信会话，全量扫一遍和全量抓评论一样贵，所以按时间窗增量。私信没有同帖语境，判定时关掉语境关（`require_scope=False`），只看「有没有第一人称开口要名额」。

- 抓取失败时不写 `data.json`，只把 `status.json` 的 `result` 改成 `failed`，站点继续用上一次的数据。
- `status.json` 记录 `updatedAt` / 人数 / 本次新增，部署后可直接访问 `/status.json` 看更新时间。
- 手工删除某人：把他的 UID 写进 `exclude.json` 的 `uids`，下次抓取会跳过并把它从 `data.json` 剔除。直接改 `data.json` 删人会被下一次抓取加回来。
- 只读抓取只需要 `SESSDATA`；`bili_jct` 是写操作的 csrf，抓评论/私信都用不到。

打包有两种产物：

- `python build.py` → 部署版：`dist/index.html`、`dist/archive.html`、`dist/data.js`。数据在 `data.js`，名单更新只改这一个文件，两个约 2.8MB 的 HTML 不再重写。
- `python build.py --standalone` → `dist-standalone/`：数据内嵌的离线单文件，双击可用，发人/存档用。

定时任务在 `.github/workflows/update-amnesty-site.yml`：每 2 小时增量一次，每周日 03:17 UTC 全量对账一次，提交 `data.json`/`status.json`/`crawl-state.json`/`avatars.json`/`dist`，Vercel 通过 Git 集成自动部署。仓库根目录的 `vercel.json` 指定 `outputDirectory` 指向 `dist`，并把 `data.js`、`status.json` 设为不缓存。

注意：Vercel 只负责托管静态文件。它的 Cron 在 Hobby 计划下一天只能跑一次，且函数撑不住分钟级全量抓取，所以抓取必须留在 GitHub Actions 侧。

## 名单判定口径（amnesty-site/judge.py + keywords.json）

不是拿关键词去匹配整条评论，而是判断「这条评论是不是在要求把自己加进名单」，分四层：

1. **语境关**：先看这条评论挂在哪个内容下。同一内容里出现 `min_strong_hits`（默认 3）条以上明确申请，这条内容才算「名单语境」，其下的模糊表达才放行。讲别的东西的视频下面，「申请」「我也要」不收。
2. **强命中**：出现 赦免/特赦/免死/铁券… 直接收。同音错字不用维护表：转拼音后匹配 `teshe`/`shemian`，特摄、特奢、射免、涉免都能命中（装 pypinyin 生效，没装就用 `homophone` 内置表兜底）。
3. **意图命中**：我也要/我我我/申请/加我/+1… 且必须带第一人称（申请、报名、排队、+1 除外），再过语境关。命中 `veto` 列表（token/账号/接码/资源…）的整条丢弃——那是在申请别的东西，不是在申请名单。
4. **模型判灰区**：意图命中的评论交给模型二分类，**喂给模型的不只是评论本身**，还包括：所在内容里有几条明确申请、别人原话示例、同帖前后各一条邻居评论、渠道（评论还是私信）。私信也过模型，只是不走语境关——私信是一对一开口，本身就是语境。

默认模型后端是 **Jev**（TypeSafe System One，`jev.py` 里现成的 JevGate，钥匙轮换、失败冷却都复用）：一个请求带一整批 noul 问题（每条灰区评论问一次「作者是否在申请加入名单」），概率 ≥ `jev.noul_threshold`（默认 0.45，压在 0.5 以下对应「宁可多收」）就收。实测一批 5 条 1.4 秒、noul 值 0.79–0.97；近 24h 的 89 条真实私信里 86 条被规则层排掉、真正进模型的只有灰区，成本可忽略（$0.042/M input、输出免费）。Jev 挂了灰区全收（口径同 rules），不阻断抓取。

判定口径用参数切换：`--judge jev`（默认，规则+同音+Jev 批量判灰区）、`--judge llm`（OpenAI 兼容模型）、`--judge rules`（灰区全收，不调模型）、`--judge words`（旧的纯关键词，用于对照）。Jev 钥匙：本地读根目录 `.jevkey`（已被 .gitignore 覆盖），CI 里配 Secret `TYPESAFE_API_KEYS`（多把钥匙用逗号分隔）。

要改口径改 `amnesty-site/keywords.json` 就行：`strong` 直接收、`intent` 需语境、`veto` 整条丢弃、`homophone` 错字表、`scope.min_strong_hits` 语境阈值、`jev.noul_threshold` Jev 收录阈值、`author_names` 排除账号。

每条被收录的评论在 `data.json` 里带 `via`（strong:特赦 / jev / llm / rules）和 `why`（模型给的理由；Jev 记 noul 概率，如 `jev 0.93`），被质疑「凭什么有他」时能翻出当时的原话和依据。

离线试跑：`python amnesty-site/judge.py --csv 某评论.csv --mode jev --limit 50`。
